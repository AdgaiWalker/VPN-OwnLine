# Agent 操作契约

> 这份文件写给**在别人机器上干活的 AI**。你读到这里，说明用户把本仓库交给了你。
> 下面这些不是建议，是边界。

## 1. 你只能动这些路径

| 路径 | 用途 |
|---|---|
| `/opt/ladder` | 本仓库的 clone |
| `/opt/web` | 面板代码与静态页 |
| `/opt/web-data` | 节点表与密钥（700；`nodes.json` / `tc.json` / `status.json`）|
| `/opt/sing-box` | 代理程序与配置 |
| `/opt/subconv` | 订阅转换 |
| `/etc/caddy/Caddyfile` | 反代与订阅路由 |
| `/etc/systemd/system/{admin,probe,usage-refresh,subconverter}.*` | 服务单元 |

**其他任何地方都不要碰。** 用户机器上很可能还跑着宝塔、nginx、数据库、别的网站。

## 2. 装好之后，操作一律走 API

装完之后唯一允许的写入口是面板 API（`/api/*`）。

- 不要直接编辑 `nodes.json`
- 不要 ssh 上去改 sing-box 配置来"加个节点"

理由：面板和你是同一个系统的两个入口。两条路都改文件，就会出现两份互相矛盾的真相。

## 3. 密码与密钥

| 规则 | 说明 |
|---|---|
| 不打印 | 除安装脚本要求复述一次，任何输出里都不出现 password / SecretKey / 私钥 / token |
| 不落盘 | 不要把用户密码写进任何文件或环境变量 |
| 不转发 | 不要把凭据贴进 commit、issue、日志 |

## 4. 必须停下来问的三件事

1. **删除**任何节点之前
2. **重置**任何密码之前
3. **重装**任何机器之前

这三个都不可逆（或代价高）。不确定就当需要问。

## 5. 判断"完成"的唯一标准

不是你说完成，是**命令输出说完成**。

| 场景 | 完成判据 |
|---|---|
| 安装 | `./scripts/verify.sh ...` 输出 **0 失败** |
| 加节点 | `GET /api/nodes` 里能查到，且 `health` 不是 `port/tls/proxy` |
| 修故障 | 用户原来说的那个症状消失了，且能复现出"好了"的证据 |

**没有输出证据 = 没完成。** 这个项目的历史上出现过 5 次"页面不报错但其实是坏的"，都记在 `docs/08-LESSONS.md`。

## 6. 失败时怎么做

1. 停下来
2. 把**原始报错**贴给用户，不要翻译成"出错了"
3. 说明你改过什么（如果你已经改过）
4. 不要连续重试三次以上同一动作

## 7. 不要做的事

- 不要"顺手装个新版本"——版本必须锁在 `deploy/install.sh` 里写的那个
- 不要在用户没要求时改系统时区、语言、字体（这和本工具无关）
- 不要为了让检查通过而修改检查命令
