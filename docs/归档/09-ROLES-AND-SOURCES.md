# 来源与状态：一台机器到底算什么

> 读这一页能搞清：**节点从哪来、它怎么出网、坏了怎么读状态。**

---

## 1. 节点从哪来

| 来源 | 怎么来的 | 我们对它有控制权吗 | 能自测吗 | 能换密钥吗 | 进订阅吗 |
|---|---|---|---|---|---|
| **自建** | 面板里填 IP + 密码/私钥，自动装 | 有（有 SSH） | 能 | 能 | 是（除非自测失败） |

> 2026-10-27 起只支持自建。「粘贴别人的 `vless://` 链接」已经从代码和面板里移除
> （原因见第 4 节）；历史数据里如果还留着标记为 external 的节点，只会显示、不能新增。

---

## 2. 节点就是节点

产品上**不再让用户选「出口 / 中转」**。用户只做一件事：选机器、填密码、点安装。

系统在装之前自动判断：

```text
目标机能直连国外？
  ├─ 能   → 直接出网
  └─ 不能 → 自动挑一台当前最快的海外节点，借道出网
```

- 北京、广州这类机器也会正常显示、正常进订阅。
- 如果一台海外节点都没有，国内机器会**直接拒绝安装并说明原因**，不会装出一个“连上没网”的节点。
- 界面上不需要出现“出口 / 中转”这两个词；内部仍保留 `role` 字段用于生成 sing-box 配置和自测，但它不是用户选项。

---

## 3. 状态（health）怎么读

| 值 | 含义 | 下一步 |
|---|---|---|
| `ok` | 端口通、握手成功、真实代理能出网 | 无 |
| `port` | 端口连不上 | 查云防火墙 / 服务是否在跑 |
| `tls` | 端口通但握手失败 | 服务没起来，或配置不对 |
| `proxy` | 机器活着，但代理连不通 | 查密钥 / 路由 / 落地配置 |
| `role_mismatch` | 自动判断后出口仍在中国 | 重新自测；检查目标机网络 |
| `landing` | 借道入口通，但连不上落地 | 查落地节点是否还活着 |
| `blocked` | 代理和 SSH 都不通 | 可能被墙，换 IP |
| `timeout` | 安装超时 | 看原始输出 |
| `unknown` | 还没测过 | 等 60 秒探活跑一轮，或点「体检」 |

---

## 4. 外部节点（已移除）

这一节保留，是为了记住为什么砍掉它。

曾经支持粘贴别人给的 `vless://` 链接进订阅。问题是：

- 我们没有那台机器的 SSH，**没法验证它真能出网**
- Reality 的特性是任何握手都会成功，只测 TCP/TLS 会把参数错误的节点误判成在线
- 也不能替它换密钥、查流量、排故障

结论是**只能显示「未验证」，不能给绿灯**——一个永远不能确认可用的节点，维护成本大于收益。
2026-10-27 删除 `/api/paste` 和面板入口，只保留自建。

---

## 5. 接入方式：密码还是私钥

| 方式 | 什么时候用 | 注意 |
|---|---|---|
| root 密码 | 默认 | 部分云禁止 root 密码登录 |
| SSH 私钥 | 密码登录被禁、或更安全 | 私钥只用于本次安装，不落盘、不进日志 |
| 非 root + sudo | 云厂商默认用户 | 在「高级」里改用户名，目标用户需要免密 sudo |

私钥在服务端只存在于两个地方：内存、`0600` 的临时文件（任务结束即删）。
`/opt/web` 全目录搜不到私钥片段——这是验收项之一。

---

## 6. 一页流程图

```text
买机器
  │
  └─ 面板填 IP + 密码/私钥
       └─ 预检 → 判断能否直连
            ├─ 能   → 配成直连节点
            └─ 不能 → 自动借道最快海外节点
                 └─ 自测（端口 → 握手 → 真实出口）
                      └─ ok → 进订阅
```
