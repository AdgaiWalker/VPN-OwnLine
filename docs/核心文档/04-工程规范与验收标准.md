## 1. 开发与架构底线标准（Development Standards）

### 1.1 轻量技术栈与依赖边界

以[轻量技术方案 v1.3](03-技术方案-全自动化装配中枢架构方案.md)为实施基线。生产坚持单轨主控，采用 Python 3 标准库（admin.py + nodekit），彻底废除 Flask / Waitress / SQLite 等冗余双轨实体。远程检查与控制使用 Paramiko（在独立 venv 中安装锁定版本的依赖 requirements.lock）。

- 前端采用原生 HTML/CSS/JavaScript ES Modules，由 Caddy 托管静态资源；生产不依赖 React、Node.js 或前端构建服务。独立原型的 React/Vite 选择不扩展为生产要求。
- 控制面采用 Python 3 标准库，由 systemd 托管；配置持久化采用原生 JSON，保留代码与数据分离。不新增 Redis/Celery、MySQL/PostgreSQL、微服务、容器编排或内置 AI。
- 运行依赖在 venv 内锁定版本与哈希（requirements.lock），部署优先使用匹配目标平台的预构建包，不在生产机器追随浮动版本。
- 代码与数据分离：`/opt/web` 存程序、静态资源及只读 venv，root 所有；`/opt/web-data` 为专用服务账号所有、0700，存配置与状态底账。临时运行资料位于 `/run/evergreen/`。
- API 进程遵循最小权限原则，不给 Web 接口通用 root 命令执行能力；远端操作通过 `remote_config.py` 执行白名单配置重写与出网验证。

### 1.2 纯函数架构与配置防漂移标准
* **无副作用纯函数**：订阅生成、熔断判定、端口仲裁、配置模板等计算逻辑保持可测试纯函数；SSH、服务启停和数据写入等副作用隔离在执行层，离网检查使用替身验证边界。
* **配置唯一形状来源**：`nodekit/templates.py` 是各节点配置的唯一基准。任何线上配置改动必须同步回填模板，通过 `python3 scripts/drift.py` 严格校验配置无漂移。
* **单一写入口**：用户变更经面板 API 校验并创建任务，worker 执行；定时器使用同一受控业务函数与目标锁。节点底账读改写必须使用跨进程锁和原子替换，不用各进程独立的线程锁代替。不得绕过任务边界手工修改受管配置。

## 2. 安全红线与操作契约（Security Redlines）

### 2.1 凭据“三不”原则
1. **不打印**：任何脚本、日志、测试输出中，绝对不得输出 root 密码、云厂商 SecretKey、UUID、私钥、订阅 Token。
2. **不落普通持久存储**：临时 SSH 密码、私钥与新管理密码不进入 SQLite、JSON、URL、普通临时文件、命令行或环境变量值；worker 内存与受限进程通道用于交接，进程丢失时重新输入或确认恢复。长期云授权与临时凭据分开。
3. **不提交**：Git 仓库中严禁出现任何真实机房的连接密钥与敏感配置。

### 2.2 鉴权与边界防线
* **管理接口鉴权**：所有管理性 API（增删节点、自愈、备份还原）强制走 Caddy 的 HTTP Basic Auth 认证。
* **订阅防遍历**：订阅链接强制使用 32 位高熵随机 Token（`/s/{token}`），数学上杜绝穷举遍历。
* **合规与伦理边界**：本系统仅做个人专属网络连通工程，**严禁修改系统时区、浏览器语言、字体、Intl 区域去伪造虚假海外身份**。

### 2.3 必须停下来向用户确认的三件事
1. **删除**任何现有节点之前；
2. **重置**任何服务器密码之前；
3. **重装**任何云主机操作系统之前。

## 3. 高可用与系统级容错标准（HA Standards）

| 场景 | 硬性标准与容错指标 |
|---|---|
| **流量防超额熔断** | 监控到月度流量达到 **85%** 刚性红线，必须在 10 分钟内执行**远程真机物理断流（`systemctl stop sing-box`）并在订阅层同步剔除**，远程命令成功后才更新熔断状态；失败保留原状态并在下轮重试，单节点异常不阻断其他节点。仅有效用量低于 85% 时允许恢复，未知或无效用量不得解除熔断。该机制降低超额风险，不保证零费用。 |
| **装前 3 秒连通性排雷** | 连接检查先探测用户选择的 SSH 端口（默认 22），初始 TCP 超时建议 3 秒，随后进行受控只读检查。连接失败必须弹出人话指引（提示检查开机与安全组），严禁直接抛出 `Permission denied` 等生涩技术堆栈。 |
| **动态端口仲裁** | 遇 443 端口被 Nginx/宝塔占用，系统必须自动降级到 `8443` 或 `20443`，绝不允许强行抢占导致原建站业务崩溃。 |
| **中继高可用冗余** | 国内中继节点必须配置双落地通道（主出口 + 备用出口），依托 sing-box 原生 urltest（30秒周期）实现主链路受阻无感自动倒换。 |
| **单节点原地自愈** | 节点探活异常时，先说明中断影响并确认，只针对已接管的 sing-box 执行修复和实际验证；按真实阶段反馈，不承诺固定 5 秒完成。85% 用量保护按已确认例外执行。 |

## 4. 交付与验收硬性判准（Definition of Done）

任何功能开发、漏洞修复或重构，必须通过以下**两道刚性检验门禁**才算完成：

```mermaid
flowchart LR
    Dev["代码编写与修改"] --> G1{"门禁一：全离网单测<br/>./scripts/test.sh"}
    G1 -->|"304项 100%全过"| G2{"门禁二：生产端到端验收<br/>./scripts/verify.sh"}
    G1 -->|"哪怕1项失败"| Reject1["打回修复"]
```

### 门禁二：生产真机端到端验收（Production Verification）
* **执行指令**：`./scripts/verify.sh https://<主控域名:端口> <账号> <密码> <Token>`
* **硬性标准**：**21 项真实验收用例全部通过（0 失败）**。
* **检验清单**：
  * **访问控制**：未授权拦截（401）、认证通过（200）、直接访问非法路径（404）、伪造 Token 遍历（404）；
  * **订阅聚合与标头**：Clash 节点数与 Base64 节点数严格一致且大于 0；`/s/{token}` 与 `/s/{token}/clash` 真实透传标准 `Subscription-Userinfo` 响应标头且字段数值完整有效；
  * **核心接口**：节点查询（200）、探活数据（200）、跨站请求拦截（403）；
  * **输入校验**：非法 IP / 域名录入阻断（400）；
  * **系统解法验证**：中继多落地状态接口（200）、85% 流量熔断接口（200）、熔断监控真实数值校验（准确率 100%）、生命周期到期标记校验。

## 5. 验收铁律（反敷衍法则）

1. **拒绝“无报错即成功”**：必须在 `ss -tulpn` 里看到监听端口、在订阅里取到对应节点、并在真实客户端测出公网出口 IP。
2. **一次只改一个变量**：严禁多处并发修改；改完立即跑 `./scripts/test.sh` 验证。
3. **交付必须给证据**：任何交付汇报必须附带测试输出摘要，严禁口头声明“已完成”。
