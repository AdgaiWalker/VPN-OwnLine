# 角色与来源：一台机器到底算什么

> 读这一页能搞清：**节点从哪来、它干什么用、坏了怎么读状态。**

---

## 1. 三种来源

| 来源 | 怎么来的 | 我们对它有控制权吗 | 能自测吗 | 能换密钥吗 | 进订阅吗 |
|---|---|---|---|---|---|
| **自建** | 面板里填 IP + 密码/私钥，自动装 | 有（有 SSH） | 能 | 能 | 是（除非出故障） |
| **中转** | 自建时角色选「中转」 | 有 | 能（测入口+落地） | 能 | **否** |
| **粘贴** | 别人给的 `vless://` 链接 | **没有** | **不能** | **不能** | 是（标「外部」） |

---

## 2. 角色：出口 vs 中转

```
出口（exit）      客户端 → 这台 → 直接出网
中转（relay）     客户端 → 这台 → 落地节点 → 出网
```

**怎么选**：

- 机器在**海外** → 出口
- 机器在**国内**（或线路好但出不去）→ 中转，落地选一台海外出口

**为什么中转不进订阅**（决定 D1）：

本期没有做"客户端直连中转再跳"的自动路由。中转进了订阅，用户选中它会得到
"连上了但没网"，比看不到更难排查。

> 等到真的需要低延迟链路时再放进来，那时候才做链式转发。

---

## 3. 状态（health）怎么读

| 值 | 含义 | 下一步 |
|---|---|---|
| `ok` | 端口通、握手成功、出口正常 | 无 |
| `port` | 端口连不上 | 查云防火墙 / 服务是否在跑 |
| `tls` | 端口通但握手失败 | 服务没起来，或配置不对 |
| `role_mismatch` | 出口 IP 在中国，却设成了出口 | 改成中转 |
| `landing` | 中转入口通，但连不上落地 | 查落地节点是否还活着 |
| `blocked` | 连续失败但实例在运行 | 可能被墙，换 IP |
| `timeout` | 安装超时 | 看原始输出 |
| `unknown` | 还没测过（外部节点恒为这个） | 外部节点测不了，见下 |

---

## 4. 为什么外部节点没有绿灯

探活做的是 TCP + TLS 握手。

**Reality 的特性是：任何握手都会成功**——服务端会回落成一个真实网站。

所以对别人的节点，我们的"握手成功"只证明**那个端口上有 TLS**，
不证明**参数对得上**。参数错一个字符，老式探活照样绿灯。

**结论**：外部节点一律显示「未验证（外部节点）」，不给绿灯。

> 这条是我们自己踩出来的：验证代码第一版用 `CONNECTED` 判断，
> 对普通 HTTP 端口也返回"通过"。详见 [03-FAILURE-MODES.md](03-FAILURE-MODES.md)。

## 5. 接入方式：密码还是私钥

| 方式 | 什么时候用 | 注意 |
|---|---|---|
| root 密码 | 默认 | 部分云禁止 root 密码登录 |
| SSH 私钥 | 密码登录被禁、或更安全 | 私钥只用于本次安装，不落盘、不进日志 |

私钥在服务端只存在于两个地方：内存、`0600` 的临时文件（任务结束即删）。
`/opt/web` 全目录搜不到私钥片段——这是验收项之一。

## 6. 一页流程图

```
买机器
  │
  ├─ 海外 → 角色=出口 ──┐
  │                      ├─ 预检 → 安装 → 自测 → 进订阅
  └─ 国内 → 角色=中转 ──┘                    │
       └─ 落地=某台出口                      └─ 中转：不进订阅

别人给链接 → 粘贴 → 校验字段 → 进订阅（标「外部」，不给绿灯）
```
