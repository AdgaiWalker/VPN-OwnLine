## 阶段交接摘要

本阶段采用最简单的 Mac 本地入口：用户双击启动文件，此后在网页完成 SSH 连接检查、确认安装和获取后台交付信息。Mac 直接连接用户指定的 Linux 服务器，不经过本项目提供的中间服务器；SSH 密码、私钥及私钥口令只在本机内存中使用。手机和其他电脑直接安装的能力本阶段没有实现。

已完成的工作：

1. 前期仓库审查与可信交付修复已落地，覆盖服务归属校验、安装目标身份绑定、独立后台交付、可信下载及升级失败恢复等路径；方案与历史生产验证见 [可信交付修复方案](06-trusted-delivery-plan.md)。本轮临时测试未修改既有生产节点。
2. 从 GitHub 准备新的本地副本 `/Users/happy/Desktop/OwnLine-clean`，与原开发仓库分开，供用户按真实新用户流程操作。
3. 实现根目录 `启动安装.command`、只监听本机的网页服务、直接 SSH 安装执行器，以及网页中的连接检查、指纹确认、安装确认、状态查询、初始密码交付和退出清理。
4. 在专用腾讯云空白 Debian 12 上跑通用户操作的安装闭环；用户完成首次改密、Shadowrocket 导入并反馈可用。
5. 补做独立协议出网、订阅解析及刷新、认证和会话保护、重复安装及页面重载检查；全量离线门禁重跑 776 项通过。逐项证据见下表。
6. 关闭本地安装服务与隔离客户端，确认云测试机、系统盘及专用安全组已清理。测试资源已不存在，不能继续使用旧后台或旧线路。

交接时原仓库分支为 `codex/trusted-delivery`；新副本分支为 `codex/mac-local-setup`，跟踪前者。已推送的实施及验收提交包括 `c1721f8`（Mac 入口）、`1f3f50a`（验收结果）、`77d7b6a`（云资源清理结果）。这些变更尚未合并到 `main`，不能把默认分支或 v0.6.1 发布包视为已经包含此入口。

## 未关闭的问题与边界

- 后台自动健康状态异常：健康检查提示探活数据未生成；手动测速显示 All Nodes Operational，但重载后再次显示 Checking / Unverified。手动测速有效不代表后台定时探活正常，根因和修复尚未完成。
- 安装期间只有通用等待提示，缺少当前阶段及耗时信息；本轮没有可归因的分阶段计时，不能将用户感受到的慢直接归因于某个下载源。
- 未配置腾讯云 API 凭据，因此云流量快照不可用。本轮没有实测计费用量采集或超额停机，不能声称费用保护已验证。
- 小火箭显示中国国旗的原因尚未定位。独立协议测试证明新节点出口匹配测试机；这不解释国旗来源，也不证明用户截图中的浏览器请求走了新节点。
- 未执行 Windows、Android、实体 iPhone 的完整独立验收，未执行真实加密私钥首装、安装断网/断电、失败后重试、重启恢复及长时间稳定性测试；已有对应离线覆盖不能替代这些实机测试。
- 本轮没有重新购买第二台服务器验证添加节点，也没有对用户既有生产节点注入故障。
