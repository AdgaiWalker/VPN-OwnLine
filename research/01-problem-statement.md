# 01 - 问题定义书 (Problem Statement)

> **版本**：v1.0.0 · 2026-11-09  
> **研究对象**：VPN-OwnLine 去中心化出海网络全自动装配系统  
> **研究法则**：先定义（圈定落差与边界），后分析（剖析根因），再解决（工程落地）。

---

## 一、 一句话核心矛盾 (One-line Thesis)

> **“在非技术用户迫切需要独享纯净出海专线的客观现实下，上游算力、云安全组、代理协议与客户端生态处于严重碎片化割裂状态，导致端到端装配摩擦力巨大、耗时过长，且新主机无法完成去中心化独立面板的交付自举。”**

---

## 二、 5 大核心要素锁定 (5-Factor Formulation)

### 1. 要素一：落差的客观量化 (The Quantifiable Gap)
* **期望状态 (Should-be)**：非技术用户在准备好裸服务器后，通过单命令或 Agent 交互，在 **$T \le 120\text{ 秒}$** 内全自动完成所有内核与安全网关部署，并直接获得一个**带有独立公网 URL、独立证书与独立强随机密码的专属 Web 管理面板**；客户端通过 Deep Link 在 **10 秒内一键唤起连通**。
* **现状实际 (As-is)**：用户需手动在控制台查找公网 IP、配云安全组、通过 SSH 黑屏终端敲命令、处理编译依赖超时、在国区应用商店艰难寻觅小火箭、手动对齐加密参数与 UUID。全流程人工装配时间 **$T > 60\text{ 分钟}$**，且新手配置失败率极高。
* **测量差距 (The Gap)**：存在高达 **30 倍以上的生命周期装配延迟落差**，且缺乏一套标准化的独立面板交付状态机。

### 2. 要素二：受害主体边界 (Stakeholder Boundary)
* **核心目标受众**：具备独立出海业务需求（如使用 ChatGPT/Claude、海外跨境电商、学术研究、日常看剧），但**不具备 Linux 运维、密码学配置与网络安全排障能力的非技术个人用户**。
* **非受害受众**：资深网络安全专家或具备自研能力的 DevOps 工程师（他们可以通过编写原生 sing-box 配置文件完成装配，不是本系统的第一性服务对象）。

### 3. 要素三：物理与外部客观硬约束 (Invariable Constraints)
* **法律与主权红线**：系统绝对不充当中心化公共代理运营商，不集中转接任何用户流量，不垫付云主机资金。所有流量、节点与机器资产 100% 归属于用户自身。
* **网络审查与骨干拥堵现实**：公网跨海长链路晚高峰丢包率高（20%~40%）是客观物理现象，无法假设存在无损公网。
* **宿主云环境沙箱**：云厂商轻量服务器默认防火墙拦截策略（默认仅放行 22 端口，全封其他端口）是不可绕过的外部白名单规则。
* **移动端操作系统沙箱**：iOS 严格受限于 App Store 生态沙箱，无法脱离苹果生态在后台静默安装未签名 IPA。

### 4. 要素四：反向边界锁（我们坚决不干什么 / Non-Goals）
* **Non-Goal 1**：坚决不做“卖流量”的商业机场，系统本身不持有任何公共代理节点。
* **Non-Goal 2**：坚决不介入下游客户端本身的逆向开发或 Bug 修复，下游软件的生命周期由各官方开源社区维护，系统仅负责基于标准 Deep Link 协议输出标准化订阅。
* **Non-Goal 3**：坚决不对用户云厂商 API 凭据、私钥或 root 密码做云端持久化留存。所有鉴权消耗必须遵循“纯内存瞬时消费、用完即焚、绝不落盘”的零信任原则。

### 5. 要素五：问题终结的判定与验收衡规 (Verification Criteria)
当且仅当系统满足以下 4 项物理测试时，判定本问题被彻底终结：
* **衡规 1（时间指标）**：从触发全新空白主机部署命令到终端打印出交付结果，总耗时 $\le 120\text{ 秒}$。
* **衡规 2（独立自举）**：新主机必须成功监听 `8443` 端口，自动绑定 HTTPS 证书，并能够通过浏览器访问专属 URL（`https://<新IP>:8443/`）。
* **衡规 3（首登改密安全锁）**：新主机专属面板初次访问强制重定向至 `/change-password`，必须修改临时强随机密码后方可进入。
* **衡规 4（客户端 0 参数录入）**：终端用户在新面板点击“一键连接本机”，iOS 成功调起 Shadowrocket 并全自动写入全部节点，测试通断成功。

## 三、 现存核心问题优先级排序 (Prioritized Problem Matrix)

```
┌────────────────────────────────────────────────────────┐
│ P0: 供应链装配断裂 (延迟过长) + 新主机独立面板自举缺失   │
├────────────────────────────────────────────────────────┤
│ P1: 缺乏网络体验主动唤醒机制 + 缺乏用户自然语言意图映射 │
├────────────────────────────────────────────────────────┤
│ P2: 延迟测速脱离客户端本地直连 + 国内依赖拉取易超时中断 │
└────────────────────────────────────────────────────────┘
```

### 【P0 · 生存卡点】碎片化供应链装配断裂，全流程耗时过长
* **定义**：云主机采购、云防火墙规则、底层代理内核编译、客户端生态（小火箭/苹果ID/Clash）缺乏统一的自动化供应链编排，整体装配交付效率极低。

### 【P0 · 交付闭环】新主机装机未完成专属 Web 面板的独立自举 (Self-Bootstrapping)
* **定义**：当前加节点仅启动代理转发后台进程，未能全自动在新服务器上跑起一套带有独立公网 URL、独立 TLS 证书和独立账户凭据的去中心化 Web 控制台。

### 【P1 · 体验盲区】缺乏基于场景的“需求主动唤醒”机制 (Demand Awakening)
* **定义**：高阶能力（HY2 抢跑、BGP 专线中转、静态住宅原生 IP）作为冷冰冰的静态技术开关平铺在界面中，系统在面临丢包、卡顿或严苛风控时，缺乏基于网络检测的主动提醒与引导。

### 【P1 · 交互断层】缺乏从用户意图到技术模块的翻译映射 (Intent Mapping)
* **定义**：系统只能被动接收 IP、端口等硬核技术参数，无法接收并转化用户的真实场景表达（如“我要做跨境电商”、“我要用 Claude 编程”）。

### 【P2 · 认知偏差】测速数据反映服务器视角，脱离用户本地真实直连 (Local RTT Disconnect)
* **定义**：当前延迟指标由服务器探针回传，用户在客户端本地看到的并非自己手机/电脑直连节点的真实端到端 RTT 延迟与丢包率。

### 【P2 · 依赖风险】国内网络环境下安装缺乏智能测速与强行切镜像机制 (Mirror Fallback Reliability)
* **定义**：构建与部署阶段缺乏前置的网络握手测速以自动判定海外连通质量，若遇严重劣化无法做到 100% 强行无感切入国内清华源或 GitHub 镜像加速节点。
