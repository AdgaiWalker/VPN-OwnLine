# 核心问题与痛点优先级排期研究 (Core Problem Assessment)

> **创建日期**：2026-11-09  
> **研究对象**：VPN-OwnLine 架构重构、供应链整合与按需模块体验演进  
> **制定原则**：彻底消灭冗余叙事，直面客观技术卡点与真实人机交互摩擦。

---

## 一、 核心问题优先级排序 (Prioritized Problem Matrix)

### 【P0 · 生存卡点】碎片化供应链装配断裂，全流程耗时过长
* **问题现状**：云主机采购（腾讯云/AWS）、安全组/防火墙规则放行（80/443/8443）、底层代理内核编译部署、客户端生态（iOS 小火箭/美区 Apple ID/纯净版 Clash）彼此割裂。
* **核心症结**：各环节缺乏统一的自动化供应链编排流水线，用户需在多个平台与技术规范之间反复横跳，整体交付极其低效、摩擦力巨大。

---

### 【P0 · 交付闭环】新主机装机未完成专属 Web 面板的独立自举 (Self-Bootstrapping)
* **问题现状**：当前的加节点逻辑仅在新服务器上后台启动代理转发进程（sing-box），将节点挂靠在母舰控制台下。
* **核心症结**：未能全自动在新服务器上跑起一套带有独立公网 URL（`https://新IP:8443`）、独立自签/合法 TLS 证书以及独立账户凭据的完整私有 Web 控制台，未实现去中心化交付。

---

### 【P1 · 体验盲区】缺乏基于场景的“需求主动唤醒”机制 (Demand Awakening)
* **问题现状**：高阶能力（HY2 抢跑、BGP 专线中转、静态住宅原生 IP）作为静态技术开关平铺在界面中，大量能力被用户长期闲置。
* **核心症结**：用户处于“不知道自己不知道”的盲区（能感知丢包卡顿，但不知该开什么模块）。系统在面临弱网抖动、丢包或封控场景时，缺乏基于网络体验检测的主动提醒与一键唤醒引导。

---

### 【P1 · 交互断层】缺乏从用户意图到技术模块的翻译映射 (Intent Mapping)
* **问题现状**：系统只是一套技术配置器，只能被动等待并接收 IP、密码、端口、UUID 等底层技术参数。
* **核心症结**：无法直接接收并解析用户的真实意图人话（如“我要登 Claude 写代码”、“我要做跨境电商/TikTok 运营”、“我打网游晚高峰卡”），缺乏由 Agent 或前端场景提示词完成的“痛点到模块装配”的桥梁。

---

### 【P2 · 认知偏差】测速数据反映服务器视角，脱离用户本地真实直连 (Local RTT Disconnect)
* **问题现状**：当前界面展示的延迟（如“1ms (探针本机)”）由服务器探针回传，属于机器自身或机房间数据。
* **核心症结**：无法反映终端用户手机/电脑到各节点的真实端到端直连 RTT 延迟与丢包率，造成用户认知偏差和数据失真。

---

### 【P2 · 依赖风险】国内网络环境下安装缺乏智能测速与强行切镜像机制 (Mirror Fallback Reliability)
* **问题现状**：系统构建与部署阶段依赖海外源与 GitHub Releases。
* **核心症结**：缺乏前置的网络轻量握手测速以自动判定海外连通质量，若遇严重劣化无法做到 100% 强行无感切入国内清华源或 GitHub 镜像加速节点，存在安装中断与超时风险。
