# 提示词 ③：修

> 用法：出问题的时候粘这段。**它比前两段更重要**——因为这是唯一一段会在你没预期的时候跑的。

---

# 症状

`<一句话描述，比如：三条节点全红了 / 能连但打不开网页 / 只有 HY2 连不上>`

# 已知环境

- 面板：`https://<域名>/`
- 主控机器：`<IP>`（Ubuntu，sing-box + Caddy + admin 都在这台上）
- 协议：VLESS+Reality（443/tcp）+ Hysteria2（443/udp）

# 排查顺序（严格按顺序，一次只查一件事）

1. **先排除本地**：让我关掉代理，打开任意国内网站。通不通？
2. **服务在不在**：ssh 上去跑

       systemctl is-active sing-box admin caddy subconverter

3. **端口在不在听**：

       ss -lntup | grep -E ':(443|8443|8099|25500)'

4. **订阅通不通**：

       curl -s -o /dev/null -w '%{http_code}\n' https://<域名>/s/<token>

5. **云防火墙**：让我去腾讯云控制台看规则，特别是 **UDP 443**（Hysteria2 用的）

**每一步都把原始输出贴给我，再判断下一步。不要连跳三步然后给结论。**

# 边界

- **一次只改一个变量**，改完立刻复测，再决定下一个
- 改 `/etc/caddy/Caddyfile` 或 `config.json` 之前先备份
- 不确定就停下来问我，不要"试着重装一下"

# 禁止

- 不要同时改多处
- 不要跳过第 1 步（大量"节点坏了"其实是家宽断了）
- 不要在没有备份的情况下重启 caddy / admin

# 完成判据

给我一张表：现象 / 查到什么 / 结论 / 下一步。查不出来的就说查不出来，不要编。
