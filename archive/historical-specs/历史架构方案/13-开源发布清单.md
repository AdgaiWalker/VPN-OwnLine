## 3. 配置的唯一来源：模板 + 漂移检查

这一节是整个仓库最容易被破坏的约定，单列出来。

### 问题是什么

`templates.py` 早就有，但它只在「安装那一刻」被用过一次。之后所有改动都是直接在服务器上手工改的——
结果模板和线上悄悄脱节：硅谷多了个 HY2 入站，模板生成不出来，谁都不知道。

**模板不会自己保持正确。必须有人定期对账。**

### 形状

```python
# 仓库/server/nodekit/templates.py
exit_config(port, uuid, sni, private_key, sid, hy2=None)   # 出口
relay_config(port, uuid, sni, private_key, sid, landing)   # 中转
```

- `hy2=None` → 只有 Reality 一个入站
- `hy2={...}` → 再加一个 Hysteria2 入站（UDP，可与 Reality 共用端口号）
- 两个函数**只返回 dict，不落盘**——落盘和 systemd 由 provision 负责

### 对账命令

    python3 scripts/drift.py            # 默认查 walker-sv / walker-bj
    python3 scripts/drift.py <ssh别名>  # 查指定机器

做法是**往返比对**：从线上配置反推参数 → 用模板重新生成 → 逐字段比。
输出 `✓ 与模板一致` 才说明模板覆盖了这台机器的全部现状。

### 一条硬规矩

> **改了线上配置，必须回填模板。否则 `drift.py` 会报漂移——这是故意的。**

漂移不是"脚本太严"，是"模板已经不能描述现实了"。放任下去，模板就变成骗人的东西。

### 新增一个协议 / 一个入站类型时的三步

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 改 `templates.py`，加可选参数（默认 None，保证老调用不变） | 不传参数时生成的配置与改之前完全一致 |
| 2 | 加 `templates_tests.py` 用例 | 至少覆盖"带它"和"不带它"两种 |
| 3 | 跑 `drift.py` | 线上那台能生成出来 → 一致 |

**2026-10-27 的 HY2 就是按这三步做的**，可以直接照抄。

## 5. 陌生人演练怎么算通过

3. 浏览器打开面板，设密码
4. 加一台机器（可以是第二台 VPS，也可以就是这台）
