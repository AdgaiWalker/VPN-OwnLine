## 3. 许可证结论（决定"能不能抄代码"）

> 这一节在写方案前必须先看，否则会埋法律债。

| 项目 | 许可证 | 能否抄代码 | 结论 |
|---|---|---|---|
| fscarmen/sing-box | **GPL-3.0** | ❌ **不能** | GPL 有传染性：抄进来，整个仓库必须变 GPL-3.0。我们仓库是 MIT，会等于放弃"别人随便用"的自由 |
| reality-ezpz | **Apache-2.0** | ✅ 可以（保留 NOTICE）| 可借鉴检测逻辑 |
| wulabing/Xray_onekey | **MIT** | ✅ 可以 | 最安全，可参考 |
| Sub-Store | **AGPL-3.0** | ❌ 不能抄 | 且作为服务提供需开源；我们也不需要它 |
| subconverter | GPL-3.0 | ⚠️ 仅进程调用 | 我们只是调用它的二进制，不分发修改版 → 可以 |
| sing-box | Other（GPL-3.0 + 例外）| ⚠️ 仅进程调用 | 同上，调二进制可以 |

**关键结论**：

> **fscarmen 那个脚本只能"读思路"，不能"抄代码"。**
> 我们要做的是**独立实现同样的四件事**（发行版判断、依赖安装、systemd 处理、架构识别），
> 而不是复制它的函数。

**代价**：M1 多花 1 天。**换来的是仓库保持 MIT**——这直接决定以后能不能"给别人用"。

## 5. 模块设计

### M1 · 预检 preflight（对应 FR-1）

**目标**：在装任何东西之前，确定这台机器"能不能装"。

| 检查项 | 命令 | 失败处理 |
|---|---|---|
| 系统 | `cat /etc/os-release` | 非 Linux → `unsupported_os` |
| 架构 | `uname -m` | 非 x86_64/arm64 → `unsupported_arch` |
| systemd | `command -v systemctl` | 无 → `no_systemd`（走降级：nohup）|
| 磁盘 | `df -m /` | <200MB → `disk_full` |
| 网络出口 | `curl -m 5 -o /dev/null -w %{http_code} https://www.baidu.com` | 失败 → 继续（可能只封外网）|
| 已有安装 | `test -f /opt/sing-box/sing-box` | 存在 → 走"重装"分支（二次确认）|

**参考来源**：reality-ezpz（Apache-2.0）与 wulabing（MIT）的检测思路；**代码独立实现**。

### M2 · 安装 install（对应 FR-1 / FR-2）

三步，全部幂等：

1. **拉包**：4 源按速度排序 → 每源独立超时 → SHA256 校验（现有逻辑，保留）
2. **落配置**：按角色选模板
   - `exit`：inbound vless+reality（现有模板）
   - `relay`：inbound vless+reality + **outbound 指向落地** + route 规则
3. **起服务**：systemd unit（现有），`enable --now`，`is-active` 校验

**私钥支持（新增）**：

```bash
# 私钥临时落盘，600，trap 清理
umask 077
KEY=$(mktemp /tmp/.lk.XXXXXX)
printf '%s\n' "$PRIVATE_KEY" > "$KEY"
trap 'rm -f "$KEY"' EXIT
ssh -i "$KEY" -o IdentitiesOnly=yes -o StrictHostKeyChecking=no ...
```

**关键点**：私钥**只存在于内存与临时文件**，绝不写入 nodes.json、绝不落日志。

### M3 · 自测 verify（对应 FR-3）

按角色分两条路径：

```
exit   : TCP(port) → TLS握手 → ssh 进去 curl api.ipify.org → 比对 ip-api 国家
relay  : TCP(port) → TLS握手 → TCP(落地 host:port)
```

**为什么 exit 要 ssh 进去取 IP**：国内机器访问 `api.ipify.org` 会被拒（实测 connection refused），
所以只有 exit 节点（海外）能做这一步。

**输出**：`ok / port / tls / role_mismatch / timeout`，写入 nodes.json。

### M4 · 角色与配置模板（对应 FR-2）—— ❌ 已废，仅存档

中转模板的核心差异：

```json
{
  "inbounds": [ { "type": "vless", "listen_port": 443, ... } ],
  "outbounds": [
    { "type": "vless", "tag": "landing",
      "server": "<落地 host>", "server_port": 443,
      "uuid": "<落地 uuid>", "flow": "xtls-rprx-vision",
      "tls": { "enabled": true, "server_name": "<sni>",
               "reality": { "enabled": true, "public_key": "<pbk>", "short_id": "<sid>" } } },
    { "type": "direct", "tag": "direct" }
  ],
  "route": { "rules": [ { "outbound": "landing" } ] }
}
```

**D1 的落地**：中转节点写入 nodes.json 时打 `role=relay`，`render()` 时**跳过**——不进订阅。

### M5 · 粘链接（对应 FR-4）

```python
# 解析 vless://uuid@host:port?k=v#name
u = urllib.parse.urlparse(link)
q = dict(urllib.parse.parse_qsl(u.query))
need = ["security", "pbk", "sid", "sni", "type"]
missing = [k for k in need if not q.get(k)]
if missing: return 400, "链接缺少 %s" % missing[0]
```

写入时：`source=external, health=unknown`，**不参与"更换密钥"**。

### M6 · 订阅渲染（已有，不改）

`render()` 已实现：nodes.json → vless 列表 → Caddyfile `url=` → reload。
**新增过滤**：`role=relay` 与 `health in (port, tls, role_mismatch, timeout)` 的节点不写入。

### M7 · 探活与 blocked 判定（扩展 probe.py）

```
连续 3 次失败（60s 间隔）
且 云控制台实例状态 = RUNNING
→ health = blocked（"可能被墙"）
```

需要读 `servers.json` 的 `state` 字段（已有）。

### M8 · 决策提示（对应 FR-6）

规则表（不训练模型，可解释）：

| 条件 | 建议 |
|---|---|
| role=exit 且 ms<300 且 country∈{US,SG,JP} | 「AI 首选」 |
| role=exit 且 ms<400 | 「日常可用」 |
| role=exit 且 ms≥600 | 「日常可用，AI 偏慢」 |
| health=blocked | 「可能被墙，建议换 IP」 |
| source=external | 「外部节点，未验证」 |

**每条建议必须带依据**（延迟/国家/流量），PRD 要求。

## 6. 数据模型变更

```json
{
  "name": "硅谷", "host": "1.2.3.4", "port": 443,
  "uuid": "...", "sni": "...", "pbk": "...", "sid": "...",
  "role": "exit",            // exit | relay  （新增）
  "source": "builtin",       // builtin | external （新增）
  "health": "ok",            // ok|port|tls|role_mismatch|blocked|timeout|unknown （新增）
  "exit_ip": "1.2.3.4",      // 仅 exit 节点（新增）
  "landing": { "host": "...", "port": 443, "uuid": "...", "pbk": "...", "sid": "...", "sni": "..." }  // 仅 relay（新增）
}
```

**兼容性**：旧节点无新字段时，默认 `role=exit, source=builtin, type=vless`（读时补默认值，不改文件）。

> `role` 字段**保留但不再参与产品逻辑**（07 已删掉角色概念）；`type` 决定订阅里生成 `vless://` 还是 `hysteria2://`。

## 8. 复用矩阵

| 能力 | 方案 | 理由 |
|---|---|---|
| 协议实现 | **复用** sing-box 官方二进制 | 自研不现实 |
| 发行版检测 | **参考思路，独立实现** | fscarmen 是 GPL，不能抄 |
| 依赖安装 | **参考 reality-ezpz（Apache-2.0）** | 可借鉴，需保留 NOTICE |
| 下载与校验 | **复用现有**（4 源 + SHA256）| 已踩过坑，稳定 |
| 订阅转换 | **复用** subconverter | 已在跑 |
| 订阅聚合 | **不引入 Sub-Store** | 我们只有一个源，10 行拼 URL 就够；引入 AGPL + Node 运行时，成本大于收益 |
| 面板框架 | **不引入**（3x-ui/Marzban）| 踩过安全告警；且它们解决的是多用户计费 |
| 探活 | **复用并扩展** probe.py | 简单够用 |
| 决策提示 | **自研**（规则表）| 没有现成项目 |
| 客户端 | **复用** | 不碰 |

## 9. 实施顺序（每个里程碑可独立验收）

| 里程碑 | 内容 | 对应 FR | 工作量 | 验收 |
