# 18 · 防反复卡点架构与一键自愈技术方案

> 创建时间：2026-10-30 15:05  
> 目标：针对全量接入 4 台服务器（北京、广州、新加坡、硅谷）过程中遇到的四大核心卡点与摩擦点，建立系统级「事前预防 + 事中诊断 + 事后一键自愈」体系，让小白用户完全避免踩坑，出问题时无需命令行即可在网页端一键自愈。

---

## 1. 核心卡点复盘与根因分析

在本次接入过程中，主要遇到了四大类卡点：

| 序号 | 卡点现象 | 核心根因 | 潜在影响 |
|---|---|---|---|
| **卡点 1** | **残留进程劫持端口（3x-ui / xray 假端口占用）** | 历史调研或调试残留的 `3x-ui.exe` / `xray-windows-amd64.exe` 占用了 8443 端口。sing-box 启动时因端口冲突闪退，导致 TCP 端口有监听但代理握手密钥不对（`health: proxy`）。 | 用户看到端口通以为正常，但客户端翻不了墙；排查需要登机找 PID 杀进程。 |
| **卡点 2** | **Windows 与 Linux 异构环境运维断层** | 面板默认以 Linux 逻辑尝试 SSH `root@...` 并在目标机调用 `systemctl`。Windows 没有 root 用户（是 `Administrator`），服务管理是任务计划程序 (`schtasks`)，路径为 `C:\proxy\`。 | 用户直接添加 Windows 服务器会报权限被拒或命令未找到。 |
| **卡点 3** | **国内服务器误设为出口节点** | 北京、广州服务器位于中国大陆机房，受 GFW 封锁无法直连被墙站点。如果用户误选为 `exit` 角色，订阅后无法翻墙。 | 用户误配导致全盘不通，无法分清中转与落地角色。 |
| **卡点 4** | **预装 Web 环境（宝塔/IIS）端口冲突与防火墙漏放** | 新加坡机器装有宝塔面板，默认 443 端口被 Web 服务占用，只能使用 8443 等备用端口，而云安全组未放行 8443 导致外部连不上。 | 端口绑定失败或被外部安全组拦截。 |

## 3. 落地实施细节

### 3.1 事前防呆与预防（Avoidance）
1. **Windows 系统智能预设 (`web/index.html`)**：
   - 当在服务器向导中选中 Windows 机器（如 `宝塔Windows面板-9zOC` 或系统识别为 Windows）：
     - 自动将 SSH 用户名默认填充为 `Administrator`；
     - 自动将推荐端口设为 `8443`（避开 Windows 宝塔/IIS 的 443 端口）；
     - 将密码输入提示切换为 "Administrator 密码"；
     - 面板弹出友好提示："🪟 检测到 Windows 服务器：默认使用 Administrator 用户，端口推荐 8443"。
2. **中国大陆服务器强制中转约束 (`admin.py` & `web/index.html`)**：
   - 前端识别服务器区域为国内（北京、广州等）：
     - 弹出提示："🇨🇳 检测到中国大陆机房：无法直接作为翻墙出口，系统已自动配置为【国内中转】模式落地海外"；
   - 后端防呆拦截：在 `/api/addnode` 接口层增加校验，若中国大陆 IP 尝试配置为 `role: "exit"`，直接返回中文友好拦截拒绝，彻底杜绝误设。

### 3.2 事后一键自愈（Self-Healing / Repair）
1. **自愈核心模块 (`server/nodekit/repair.py`)**：
   - 跨平台抽象执行：支持 Linux (`base64` 管道安全传输) 与 Windows (`cmd.exe /c taskkill & schtasks`)。
   - 冲突进程强制清理：自动排查并杀死 `3x-ui`、`xray` 等历史遗留进程，释放目标端口。
   - 配置语法预检与优雅重启：启动前执行 `/opt/sing-box/sing-box check`，确认配置文件无误后再拉起服务。
   - 修复后实时验真：调用 `verify.run(node)` 执行真实的 SOCKS 出口拉取，确保节点真实可翻墙后才标记恢复。
2. **管理后端 API (`/api/repair`)**：
   - 单节点修复：`POST /api/repair {"name": "新加坡"}`
   - 全量批量自愈：`POST /api/repair {"all_bad": true}`
   - 联动结构化日志：修复过程记录到 `/opt/web-data/events.log`，前端可随时回溯。
3. **Web UI 操作界面呈现 (`web/index.html`)**：
   - **节点卡片直接自愈**：任何处于红灯（异常）状态的节点，卡片右侧直接出现小巧的「自愈」按钮，点击即修。
   - **节点管理菜单**：在节点的「··· 更多」菜单中常驻「一键自愈修复 · 清理冲突与重启服务」项。
   - **一键体检联动自愈**：在「一键体检」发现异常问题时，列表底部自动出现高亮大按钮「一键自愈修复所有异常节点」，用户只需点击一次，系统全自动并发/批量自愈。
